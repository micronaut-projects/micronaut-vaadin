Micronaut Vaadin controls the access to views with https://micronaut-projects.github.io/micronaut-security/latest/guide/[Micronaut Security]: the users and their roles come from Micronaut Security, and Vaadin checks them against the annotations of each view. Add the security integration:

dependency:io.micronaut.vaadin:micronaut-vaadin-security[]

=== Access to views

Annotate each view with who may see it. A view without an annotation is denied to everyone.

[cols="1,2"]
|===
|Annotation |Who may see the view

|`@AnonymousAllowed` (`com.vaadin.flow.server.auth`)
|Everyone, signed in or not

|`@PermitAll` (`jakarta.annotation.security`)
|Every authenticated user

|`@RolesAllowed("ADMIN")` (`jakarta.annotation.security`)
|The authenticated users with one of the roles

|`@DenyAll` (`jakarta.annotation.security`)
|Nobody
|===

An anonymous user who opens a view that needs authentication is taken to the login view, when one is configured: when its path is the route of a view of the application, Vaadin navigates to that view without reloading the page. A signed-in user without the required role gets an access denied error, which production mode reports as a view that does not exist.

[configuration]
----
vaadin:
  security:
    login-view: /login
----

Set `vaadin.security.enabled` to `false` to turn the access control off. To change how views are checked, define a `NavigationAccessControl` bean, or add checks with `NavigationAccessChecker` beans.

=== The current user

Inject `AuthenticationContext` to know who is signed in, with which roles, and to sign out:

snippet::io.micronaut.vaadin.docs.security.AdminView[tags="admin", indent=0, title="A view for administrators", languages="java,kotlin,groovy"]

<1> Only the users with the `ADMIN` role may see the view
<2> `AuthenticationContext` knows the user of the current request
<3> Sign the user out

`logout()` sends the browser to the logout endpoint of Micronaut Security, `vaadin.security.logout-path`, `/logout` by default.

=== Signing in

Vaadin's `LoginForm` can post the credentials straight to the login endpoint of Micronaut Security, which authenticates them with the authentication providers of the application:

snippet::io.micronaut.vaadin.docs.security.LoginView[tags="login", indent=0, title="A login view", languages="java,kotlin,groovy"]

<1> Everyone may see the login view
<2> The form posts to `/login`, the login endpoint of Micronaut Security, which wins over the view of the same path for a `POST`
<3> Micronaut Security redirects to the login failure URL, configured below, when the credentials are wrong

Keep the user in a cookie, for example a JWT with `micronaut-security-jwt`, and configure where Micronaut Security redirects:

[configuration]
----
vaadin:
  security:
    login-view: /login
micronaut:
  security:
    authentication: cookie
    token:
      jwt:
        signatures:
          secret:
            generator:
              secret: "${JWT_GENERATOR_SIGNATURE_SECRET}"
    redirect:
      login-success: /
      login-failure: /login?error
      logout: /
    endpoints:
      logout:
        get-allowed: true
----

The views can also read the user from the request: `VaadinRequest.getCurrent().getUserPrincipal()` is the `Authentication` of Micronaut Security.

=== How users are authenticated

* On the Netty server, Micronaut Security authenticates Vaadin's requests like any other request, with every authentication mechanism it supports. Vaadin's routes let every request through Micronaut Security's rules: Vaadin checks the access to its views itself.
* On a servlet container, Vaadin's requests do not pass through Micronaut's filters, so the integration authenticates them with the authentication fetchers of Micronaut Security. The fetchers see the method, URI, headers and cookies of each request, and its Micronaut session when Micronaut Session is present: HTTP Basic, a token in a cookie or a header, and an authentication kept in the session, with `micronaut.security.authentication: session`, all work.

Micronaut Security keeps protecting the controllers of the application as usual.
